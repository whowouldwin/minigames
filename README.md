# MiniGames — Story 3

Responsive single-page application for the RS School Qualifying Stage. Built with TypeScript, Vite and Sass, without JavaScript or CSS UI frameworks.

- [Live application](https://whowouldwin.github.io/minigames/)

## Run locally

Use Node.js 24 (minimum 22.12) and npm.

```sh
npm ci
npm run dev
```

```sh
npm run check         # TypeScript, ESLint, Prettier, production build
npm run typecheck
npm run lint
npm run format:check
npm run format        # Apply formatting
npm run build
npm run preview
```

For the GitHub Pages base path:

```sh
npm run build -- --base=/minigames/
```

The postbuild script copies the entry document to `dist/404.html`, allowing direct SPA URLs to load on GitHub Pages.

## Implemented scope

Home loads featured games and the Top Players leaderboard from the public REST API. The carousel supports navigation, autoplay and swipe; clicking a game opens its details.

Library loads category chips and game cards from the API. Category, all four sort options and pagination are sent to the backend in one games query with `limit=6`. Changing category or sort resets the page to 1. Pagination uses response metadata and shows at most four page buttons on desktop/tablet or three on mobile.

Game Details loads the selected game's artwork, description, specifications, ratings and records. Comments use `limit=3&sort=newest`, display the exact total count and format timestamps as relative time. Missing games have a dedicated Game Not Found state.

API-driven sections share animated skeletons, error banners with retry, distinct empty states and a reusable Snackbar with success/error variants and automatic dismissal.

A custom History API router keeps Home/Library, category, sort, page, game dialogs and Login/Register dialogs synchronized with the URL. Direct links, reloads and Back/Forward restore the corresponding state. Unknown paths show a responsive 404 page with the shared Header/Footer and a Return to Home Page button.

Authentication, favorite changes, comment posting and comment likes belong to Story 4. Story 3 uses public read requests; favorite mutations are disabled. Login/Register remain presentation dialogs with URL state.

## API and assets

The backend base URL is `https://faxb76kxra.execute-api.eu-central-1.amazonaws.com/api`. Game artwork paths returned by the API resolve to locally stored files in `public`, using the application's Vite base path. The backend URL and the app asset URL serve different destinations.

## Structure

- `src/app`: application composition and synchronization of dialog state.
- `src/api`: typed public API requests and response types.
- `src/router`: URL parsing, route serialization and History API navigation.
- `src/pages`: Home, Library and Not Found views.
- `src/components`: UI components, controllers and Sass.
- `src/utils`: shared formatting helpers.
- `src/styles`: tokens, mixins, typography and global styles.
- `src/assets` and `public`: locally stored fonts, icons and game artwork.
- `docs/review`: screenshots for pull-request review.

Page content is generated by TypeScript. Static HTML contains metadata and the entry script only.

## Git workflow and deployment

Story 3 task branches target `story-3` through separate pull requests. Task PRs are merged with merge commits. The final `story-3` → `story-2` pull request remains **open and unmerged** for cross-check review.

Husky validates commit messages and checks lint/formatting before push. GitHub Actions checks types, lint, formatting and the production build. Pushes to `story-3` publish GitHub Pages with the `/minigames/` base path; pull-request checks build without deploying.
